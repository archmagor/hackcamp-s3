## 机会卡 A（入口：新能力）— OddsGate

> 关联：产品方案 `idea-oddsgate.md`（定稿 2026-10-23）。本卡是该方案的机会卡视图。

- **谁，在什么场景下**：跑自主 client agent 参与受监管消费的普通用户；首垂直为**欧洲足球博彩数据**。用户的 agent 需在无人监督（A2A，每笔购买无需真人介入）下自主询价、购买、记账三类数据产品——赔率快照、球队/球员状态、胜平负概率；而卖方必须在每笔成交前完成合规准入（买方已成年 + 持牌辖区居民）。

- **现在怎么做，哪一步最别扭**：现有 agent 支付方案只解决"付钱通道"，合规门禁要么不做、要么靠后端 policy 或人工 KYC。别扭在**身份合规与支付解耦、且卖方要么接触 PII 要么留合规缺口**——卖方做 KYC 就得收集姓名/生日/居住国（GDPR 风险），不做就有未成年/非持牌辖区买入的口子；agent 端限额又写在 prompt / 后端 policy，被 prompt injection 或绕过时既超付又无授权留痕，事后只能看链上转账，看不到"人类究竟授权了什么、授权凭证是否仍有效、是否可被第三方独立复核"。

- **我改变哪一步**：把合规门禁做成**零知识、不接触 PII、密码学绑定 agent、可审计、可撤销**的四门校验。① 买方首次授权（真人只在场一次）时用 Concordium 身份出组合 ZKP（age≥18 + countryOfResidence ∈ 持牌辖区 + ContextString 绑 client agent token id），产出一份**审计记录（委托证明）**，VRA/VAA 双锚点上链；② 此后每笔购买 agent 携审计记录复验，卖方全程不接触任何 PII；③ 付款走 **x402 V2 sponsored**——sponsor 代付 CCD 手续费，买方只付标价 EUDemo；④ 成交与拒绝全量写 `/sales` 审计账本，购买授权随时可撤销（换钥 / Registry 状态 / 新鲜度过期）。

- **用到的新能力 / 赛事要求的技术**：Concordium **Verify and Access V1**（属性 ZKP + VRA/VAA 链上锚定 + 委托证明复验）+ **Agent Registry CIS-8004 / CIS-8**（agent 问责 + 把 Base Sepolia ERC-8004 agent 跨链绑定到 Concordium）+ **Verified by Concordium badge**（Agent Card 校验）+ **x402 V2 sponsored transactions**（HTTP 层结算 + 手续费代付）+ **PLT / EUDemo**（欧元计价结算资产，decimals 6）+ **Agent Registry MCP**（只读问责查询）。覆盖赛事"≥1 个 Concordium 组件"硬条件的全部六项（组件清单来源：`01-选赛卡.md` "必需集成"字段）。

- **现有替代方案（附链接）**：Coinbase **x402**（https://github.com/coinbase/x402 ，只做支付通道，不做身份合规门禁）／ **Skyfire**（https://skyfire.xyz ，agent 支付钱包，policy 层限额、无 ZKP 身份）／ **Payman**（https://payman.ai ，agent 支付抽象层）／ **ERC-4337 paymaster + session key**（https://ethereum.org/en/roadmap/account-abstraction/ ，限额靠合约逻辑，非身份级）／ **Blockbet**（Encode London 2025 Bonus，博彩责任博弈：验证身份 + PLT，但非 A2A 自主、非 sponsored、无委托证明第三方复验，见 `01-选赛卡.md` 往届获奖）。OddsGate 差异 = 身份 ZKP × agent 问责 × sponsored 支付 × 委托证明四者首次组合。链接可访问性需提交前复核。

- **为什么现在能做**：Concordium Trusted Agents Hackathon 首次把 Verify and Access + Agent Registry + x402 + PLT + sponsored tx + MCP 六件套一起开放给外部（含 EVM）agent（`01-选赛卡.md` 原文："**Can I bring an agent that lives on another chain? — Yes, that is the point.**"）；x402 在 EVM 侧已有生产 SDK；sponsored / PLT（EUDemo）付款已在 testnet 多笔实测跑通（`idea-oddsgate.md` 附录已核实：EUDemo tx `2b040e71…`，sponsor 代付 5.652936 CCD；卖方 agent #974 Active）。

- **最危险的假设**：**委托证明的第三方复验语义**——假设 server 能凭 client 每笔携带的审计记录（request + presentation + VRA/VAA tx hash）复验其有效性，并在凭证被吊销后仍能正确拒绝。三个未验证点（`idea-oddsgate.md` §8 明列）：① Verify and Access 是否支持"已存审计记录被第三方复验"这一用法，而非仅一次性在线验证；② 钱包出组合证明并经 ContextString 绑定 agent 的 UX 是否可用；③ 账户凭证吊销后，已锚定审计记录的事后复验是否回链查吊销状态（属 P1 未验证项）。任一不成立，门②（属性门）退化，核心差异化——"不接触 PII 的可复验合规门禁"——消失。

- **2 小时内能做的验证动作**：① 读 concordium-node-sdk-js（https://github.com/Concordium/concordium-node-sdk-js ）+ Verify and Access 文档，确认能否用已存审计记录离线复验 + ContextString 绑 agent token id；② 从 testnet faucet 领 CCD（`01-选赛卡.md`："test CCD comes free from the testnet faucet"），用真钱包跑一次 `requestVerifiablePresentationV1`，拿到组合证明并本地复验；③ 用已实测的 x402 sponsored 通道（EUDemo）挂上 `X-IDENTITY-PROOF` 头，验证购买请求能否携委托证明过四门。

- **推翻条件（出现什么就放弃 / 降级）**：① Verify and Access 只提供"是 / 否"在线验证、不支持审计记录第三方复验，且无兜底 → 门②退化为后端签名 + nonce，与 Skyfire / Payman 无差异 → 放弃或降级；② 钱包无法出"绑定 agent token id"的组合证明（ContextString 不支持）→ 授权与 agent 断绑 → 放弃委托证明模型；③ 凭证吊销后复验不回链查状态，且新鲜度窗口（30 天）+ 换钥 + Registry 状态三重兜底都不足以撤销 → 可撤销性承诺不成立 → 放弃。降级链（`idea-oddsgate.md` §4.4）：委托证明 → 会话窗口授权 → H2A 每笔在场（浏览器出证 + 一次性 token，已实现）。
