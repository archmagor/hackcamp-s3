# 04 链上角色（VetGate）

> 动手部分截至现在只有 Ledger.sol 上链（记录哈希，属 spike 验证）。以下回答兽医采购 agent 项目本身的链上角色。

## 链上发生的是哪个动作？
- **权限**（核心）：采购授权的发行与消耗 —— 库存低于安全线由合约解锁、一次性、消耗后才允许采购。
- **记录**：授权消耗与采购结果留痕，供审计重放。
- 身份（边缘）：兽医对采购单的签名确认。
- 不在链上：FDA/DEA 核验（链下 API）、x402 支付发起（HTTP 层，settle 由 facilitator 上链）。
- 现状：权限未动工，已实现的只有记录。

## 对应的理由？
**选理由 1：多方互不信任，需要一个中立的结算或托管方。**
诊所、agent、供应商三方互不信任 —— agent 后端可被绕过、供应商有利益冲突、诊所数据库可单方改，授权消耗必须由谁都改不了的合约强制。
（理由 3 部分适用于「记录」动作：审计方可独立重放；理由 2 只覆盖 x402 结算，非本项目核心；理由 4 是外部约束，不是设计理由。）

## 去掉链上还剩什么？
剩：采购 agent、MCP、FDA/DEA 核验、限额、回执 —— 都不需要链。
链上独有的只有两件：无授权则合约 revert（强制）；不依赖任何一方日志的公共审计。

判定：按当前成果（只有记录），链上是**可选的审计层**。
升级为必须：授权合约做出来（无授权被合约拒、授权一次性消耗），判定标准即验收条件那条失败用例。
spike 失败（Concordium 表达不了消耗语义）：老实放弃或换方向。

## 评委在哪里看到？
1. CCDExplorer 合约页 + 交易历史（提交物硬条件）。
2. Demo 视频三个时刻特写：解锁授权 / 无授权被拒 / 授权已消耗。
3. 脚本输出自带 explorer 链接。
